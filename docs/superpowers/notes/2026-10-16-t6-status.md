## 2026-10-16 — Task 3: `scripts/launch/health.py` (done first; Tasks 1-2 call it)

Stdlib only, so any Python can run it, including the bare `py` launcher.

```
python scripts/launch/health.py status [--json] [--require backend,web,sim] [--timeout 3] [--no-gpu] [--no-processes]
python scripts/launch/health.py wait <service> [--timeout 60] [--interval 1]
python scripts/launch/health.py port-free <port>
```

| Service | Check | States |
|---|---|---|
| backend | `GET :8000/api/health` → `{"status": "ok"}` | OK / DOWN |
| web | `GET :5173/` → any 2xx; tries `127.0.0.1`, then `localhost` | OK / DOWN |
| sim worker | `GET :8770/health` → `ok`, `busy` | OK / BUSY / DOWN |
| policy server | `GET :8765/health` → `ok`, `checkpoint` | OK / DOWN |
| teleop relay | `GET :8000/teleop/status`; detail says whether a sim is connected | OK / DOWN |

Plus GPU memory (`nvidia-smi --query-gpu=memory.used,memory.total --format=csv,noheader,nounits`)
and the Isaac python processes.

**Decisions:**

- **BUSY counts as up** for the exit code and for `wait`: the worker is running, it just has
  a job.
- **Default required services: backend, web, sim.** The policy server is only needed for eval,
  and the teleop relay is part of the backend. `--require` changes the set.
- **Web also tries `localhost:5173`.** Vite 5 binds `localhost`, which can resolve to `::1`
  only on Windows, so a check of `127.0.0.1` alone could call a running dev server DOWN.
  (Not reproduced here: the web server isn't running and `web/node_modules` doesn't exist in
  this worktree.)
- **URL overrides**, for tests and other ports: `PM_BACKEND_URL`, `PM_WEB_URL`,
  `SIM_WORKER_URL` (the backend's own variable) and `PM_POLICY_URL`.
- **Isaac processes = python.exe whose ExecutablePath is inside `C:\isaac\env_isaaclab`.**
  Seen live: a uv venv's `python.exe` is a launcher that starts a base interpreter
  (`...\uv\python\cpython-3.12...\python.exe`) with the same arguments, so every Isaac run
  is two processes. Only the launcher's path is in the venv, so this counts each run once.
  Matching the command line instead would count both.
- **Checks run in parallel** in `status`. On Windows a refused loopback connect takes about
  1–2 s, so five sequential checks with three services down took several seconds.
