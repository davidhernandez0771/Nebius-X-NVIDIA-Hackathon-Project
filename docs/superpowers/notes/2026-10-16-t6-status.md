## 2026-10-16 — Task 3: `scripts/launch/health.py` (done first; Tasks 1-2 call it)

Stdlib only, so any Python can run it, including the bare `py` launcher.

```
python scripts/launch/health.py status [--json] [--require backend,web,sim] [--timeout 3] [--no-gpu] [--no-processes]
python scripts/launch/health.py wait <service> [--timeout 60] [--interval 1]
python scripts/launch/health.py port-free <port>
```

| Service | Check | States |
|---|---|---|
| backend | `GET :8000/api/health` → `{"status": "ok"}` | OK / DOWN |
| web | `GET :5173/` → any 2xx; tries `127.0.0.1`, then `localhost` | OK / DOWN |
| sim worker | `GET :8770/health` → `ok`, `busy` | OK / BUSY / DOWN |
| policy server | `GET :8765/health` → `ok`, `checkpoint` | OK / DOWN |
| teleop relay | `GET :8000/teleop/status`; detail says whether a sim is connected | OK / DOWN |

Plus GPU memory (`nvidia-smi --query-gpu=memory.used,memory.total --format=csv,noheader,nounits`)
and the Isaac python processes.

**Decisions:**

- **BUSY counts as up** for the exit code and for `wait`: the worker is running, it just has
  a job.
- **Default required services: backend, web, sim.** The policy server is only needed for eval,
  and the teleop relay is part of the backend. `--require` changes the set.
- **Web also tries `localhost:5173`.** Vite 5 binds `localhost`, which can resolve to `::1`
  only on Windows, so a check of `127.0.0.1` alone could call a running dev server DOWN.
  (Not reproduced here: the web server isn't running and `web/node_modules` doesn't exist in
  this worktree.)
- **URL overrides**, for tests and other ports: `PM_BACKEND_URL`, `PM_WEB_URL`,
  `SIM_WORKER_URL` (the backend's own variable) and `PM_POLICY_URL`.
- **Isaac processes = python.exe whose ExecutablePath is inside `C:\isaac\env_isaaclab`.**
  Seen live: a uv venv's `python.exe` is a launcher that starts a base interpreter
  (`...\uv\python\cpython-3.12...\python.exe`) with the same arguments, so every Isaac run
  is two processes. Only the launcher's path is in the venv, so this counts each run once.
  Matching the command line instead would count both.
- **Checks run in parallel** in `status`. On Windows a refused loopback connect takes about
  1–2 s, so five sequential checks with three services down took several seconds.

## 2026-10-16 — Task 2: `scripts/launch/start.ps1` and `stop.ps1`

```
start.ps1 [-Backend] [-Web] [-Sim] [-Policy <checkpoint>] [-TimeoutSec N] [-LogDir DIR]
          [-SantVenv DIR] [-IsaacPython EXE] [-LeRobotPython EXE] [-BackendPort 8000] [-SimPort 8770] [-PolicyPort 8765]
stop.ps1  [-Service backend,web,sim,policy] [-LogDir DIR]
```

| Service | Command (from the notes/README) | Venv | Health wait |
|---|---|---|---|
| backend | `uv run uvicorn app.main:app --app-dir src --port 8000` | `$env:UV_PROJECT_ENVIRONMENT` / `-SantVenv`, `UV_LINK_MODE=copy` | 120 s |
| web | `cmd /d /c npm --prefix web run dev` | needs `web\node_modules` (`npm --prefix web ci`) | 120 s |
| sim | `C:\isaac\env_isaaclab\Scripts\python.exe -m sim_worker.server --port 8770 --robot franka --cameras` | Isaac | 900 s |
| policy | `C:\venvs\lerobot\Scripts\python.exe -m lerobot_tools.policy_server --checkpoint <X> --port 8765` | LeRobot | 300 s |

**Decisions:**

- **Hidden background processes**, from the repo root, so `DATA_DIR` (default `<repo>\data`) is
  the same for the backend and the worker (T4: they must share a disk).
- **Logs: stdout → `data\logs\<service>.log`, stderr → `data\logs\<service>.err.log`.**
  `Start-Process` can't send both to one file, and a `cmd` wrapper to merge them is fragile with
  spaces in paths (the main checkout's path has them). This is the same layout T2 used
  (`sim_worker_server.log` / `.err.log`). Each start overwrites that service's logs.
  `data/` is git-ignored (`/data/`), so the logs and `pids.json` are too.
- **`pids.json`** holds per service: `pid`, `start_time` (UTC, from the process itself),
  `command`, `port`, `log`, `err_log`, `started_at`. It is written BOM-less (PS 5.1's
  `Set-Content -Encoding UTF8` adds a BOM).
- **stop.ps1 checks identity, not just the PID:** an entry's process must still have the
  recorded start time (Windows reuses PIDs). A gone process, or a reused PID, is "not touched"
  and the entry is dropped. Then `taskkill /PID <pid> /T /F`.
- **Why `/T` (tree kill):** `uv run` and a venv's `python.exe` start a child that does the work,
  and `-Web` is `cmd → npm → node`. Measured in the tests: a uv venv launcher already kills its
  child when it dies (a kill-on-close job), so without `/T` the test still passed with a
  launcher-only sleeper. The test now uses a `cmd → python` tree, and the no-`/T` mutant fails it.
- **Refusals (nothing is started):**
  - sim: port taken (the plan's rule), or any Isaac-venv python process running (sprint 3's
    "at most one Isaac process"), or the Isaac python missing;
  - any service: port taken by something that doesn't answer that service's health check;
  - policy: checkpoint path missing; web: no `node_modules`; backend: no SANT venv or no `uv`.
  - A service that already answers its health check (and isn't ours) is left alone and counts
    as up. One already in `pids.json` and alive is not started twice.
- **`PYTHONPATH=<repo>\src` for the sim worker and the policy server.** Isaac's venv holds an
  editable `demo_pipeline` from `C:\dev\pm-t2`, and LeRobot's from `C:\dev\pm-t3` (T5's sprint 3c
  note: "re-point Isaac's editable demo_pipeline, or set PYTHONPATH"). Without it, the worker runs
  this checkout's `sim_worker` against another checkout's `demo_pipeline`.
- **`SIM_WORKER_URL`** is set only when `-SimPort` is given, and the backend inherits it.
- **A failed start:** if the process exits before it is healthy, its entry is removed and the log
  tails are printed. If it is alive but not healthy by the timeout, it is left running (Isaac may
  still be loading) and the message says how to stop it.
- **No `.env`** is only a note: the backend runs, and Nemotron calls fall back to the rules.

**Found while testing: don't capture `start.ps1`'s output through a pipe.** The services it
starts inherit its stdout/stderr handles, so a reader waiting for EOF waits until they stop.
- Seen: the first E2E run hung for 10 minutes. `start.ps1` had already exited, and the backend
  was healthy on its scratch port with a correct `pids.json`. Only pytest's `capture_output` pipe
  was still open (held by `uv.exe`). Stopping that backend with `stop.ps1` released pytest at once
  (`TimeoutExpired` after 300 s; Python's post-timeout `communicate()` has no timeout).
- Fix in the test: output to a file. For people: run it in a console, or redirect to a file.
  This goes in the RUNBOOK.

**Tests:** `tests/test_launch_start_stop.py`, 8 + 1 opt-in. Written before the scripts; RED:

- start: usage (exit 2); a sim refused on a taken port (no `pids.json`, no log); a sim refused
