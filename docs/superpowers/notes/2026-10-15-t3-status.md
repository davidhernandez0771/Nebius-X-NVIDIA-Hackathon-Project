## Blocked / needs a human

1. **`lerobot-train` exits 1 at every checkpoint save on Windows:** `OSError: [WinError 1314] A required privilege is not
   held by the client: '000300' -> '...\checkpoints\last'`. Cause: `update_last_checkpoint` makes a symlink, which needs
   admin rights or Developer Mode. The checkpoint itself is written first and is fine. A long run dies at its first
   `--save_freq`. Options: enable Developer Mode (a system setting; I did not touch it), or an in-repo wrapper that
   patches `update_last_checkpoint`. Your call.
2. **torchcodec 0.11.1 can't load:** `RuntimeError: Could not load libtorchcodec ... We support versions 4, 5, 6, 7,
   and 8` / `Could not find module '...libtorchcodec_core8.dll'`. The system FFmpeg is the static WinGet 9.0 build. The
   workaround in use is LeRobot's own `video_backend="pyav"` (PyAV bundles FFmpeg), passed everywhere a dataset is
   loaded or trained. `lerobot-info` still crashes on this. Proper fix: a shared FFmpeg 7/8 on PATH (an install, so
   your call).
3. **pydantic is present only through `wandb`.** `demo_pipeline` needs pydantic, but lerobot doesn't depend on it, and
   the repo goes in with `--no-deps`. With only `lerobot[dataset]` installed:
   `ModuleNotFoundError: No module named 'pydantic'`. It works today because `lerobot[training]` → `wandb` →
   `pydantic 2.14.1`. Recommendation: add `pydantic` explicitly to the lerobot venv recipe.

## Decisions I made

- **Installed `lerobot[dataset,training]==0.6.1`, not bare `lerobot`.** The bare package has no dataset stack, and
  `lerobot-train` needs `accelerate`. I counted lerobot's own extras as "lerobot". I installed nothing outside the
  approved list directly; pydantic arrived as a transitive dependency.
- **Images are stored as `video` (MP4 via PyAV)**, matching spec 8.7 ("front and wrist video"). Feature names are
  `observation.images.<camera>` for each camera in `meta.cameras`, so `front` and `wrist` as the plan says.
- **Passports go to `<dataset>/passports.jsonl`**, one row per episode: `{episode_index, demo_id, passport}`.
  `save_episode(episode_data=None, parallel_encoding=True)` has no custom metadata parameter in 0.6.1.
- **`export_episodes` validates everything before writing.** It needs equal camera sets and `meta.fps == fps` for every
  episode. The output root must not exist yet, because `LeRobotDataset.create` uses `mkdir(exist_ok=False)`. State
  and action are cast to float32.
- **Exporter tests start with `pytest.importorskip("lerobot")`.** Without it, the repo-wide `pytest` in the SANT venv
  collects `lerobot_tools/tests`, fails to import, and aborts the whole run. That would have hidden the 54/165
  baseline.
- **`train_smoke.py` runs the stock `lerobot-train` CLI** in a subprocess, not a patched copy, so the result answers
  "does LeRobot train on Windows" honestly. It enforces the sprint GPU budget (`--steps ≤ 300`, `--batch-size ≤ 8`)
  and writes everything under git-ignored `data/runs/`.
- **No unit tests for `train_smoke.py`.** The plan lists no test file for Task 3, and the run itself is the
  verification. One bug was found that way: the first steps/s figure (7.52) averaged in the warmup window and the loss
  regex matched `kld_loss`. I fixed this in `parse_train_log` and re-checked it against the same `train.log`
  (20.7 steps/s, which matches tqdm's 20.6). I did not use the GPU for a second run.
- **Peak VRAM:** I report lerobot's own torch peak (`mem_gb` 0.99). The whole-GPU nvidia-smi peak was 7184 MiB, but
  Isaac shared the GPU, and per-process numbers aren't available under WDDM.

## 2026-10-16 — Task 1 done: symlink-free checkpoints (Review Focus 4) — `ad81f83`

**Result:** a 1,000-step ACT run with `save_freq=250`, batch 8, on the synthetic dataset now **exits 0** on Windows,
with 4 checkpoints (`000250 000500 000750 001000`) and `checkpoints/last.txt` → `001000`.

- `lerobot_tools/train.py` patches `update_last_checkpoint` in both `lerobot.common.train_utils` and
  `lerobot.scripts.lerobot_train` (the latter imports it by name), then calls `lerobot_train.main()` in-process with
  `sys.argv` set. Adds `--dataset.video_backend=pyav` unless the caller sets one. Rejects `--steps > 2000` and
  `--batch_size > 8` (sprint GPU budget; constants `MAX_STEPS`, `MAX_BATCH`).
- **Choice: a `last.txt` pointer, not a directory copy.** Reasons: one checkpoint is **591 MB** (model + optimizer
  state), so a copy would double the disk and add a ~0.6 GB write per save; and `lerobot-train --resume` never reads
  `last` locally anyway. It takes `--resume=true --config_path=<step>/pretrained_model` (or that dir's
  `train_config.json`); `last` is only written, never read, in the train path (`rl/learner.py` reads it, but we
  don't use the RL learner). The wrapper's `--resume-last <output_dir>` fills `--config_path` from `last.txt`.
  `resolve_last_checkpoint(path)` takes a run dir or its `checkpoints/` dir. The pointer is written atomically
  (tmp + `os.replace`).
- **Resume verified:** 300 steps (save 150) → `--resume-last <out> --steps=450` → exit 0, the resumed log starts at
  step 350 (not 50), checkpoints `000150 000300 000450`, `last.txt` → `000450`.
- **Speed (1,000-step run):** 11.8 steps/s steady (`updt_s` ≈ 0.080 + `data_s` ≈ 0.002–0.007), first window
  0.677 s/step (warmup). Wall ≈ 22 s per 250 steps including the save. Loss 14.97 → 1.77. Torch peak 0.98 GB.
  This is slower than sprint 1's 20.7 steps/s (`updt_s` 0.047) with the same model/batch/data; the time per window
  is flat (no slowdown from saves), and nvidia-smi showed another GPU user right after (3754 MiB used, 20% util), so
  I attribute it to sharing the GPU with Terminal 2. Not re-run, to save GPU time.
- **Tests:** `lerobot_tools/tests/test_train.py` — 9 pure tests (pointer, resolve, missing pointer/step, pyav
