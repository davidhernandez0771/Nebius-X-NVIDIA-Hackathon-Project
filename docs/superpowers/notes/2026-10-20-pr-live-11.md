### Known issue: resuming an experiment frozen before `--repairer`

- **What happens.** `scripts/run_human_demo_experiment.py` always writes `repair` into the config
  (`repair=args.repairer`, from `pm/nemotron-repair`).
- **Who it hits.** Configs frozen before that flag existed have no `repair` key, `human10c`'s included. The resume
  check (`config_diff`) sees a changed setting and refuses ("frozen with other settings (repair)") unless
  `--force-config` is passed, which re-freezes the config.
- **The other flags don't do this.** `--input` and `--multiplied-only` are written only when set, for this reason.
- **Status.** Found by reading the code; no run hit it. The fix is two lines: add `repair` to the settings only
  when it isn't `rules`, and read it as `config.get("repair", "rules")`. It isn't made here (this round was docs
  only).
