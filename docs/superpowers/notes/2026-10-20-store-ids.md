# Demo ids: 8 hex digits and no repeats (2026-10-20, pm/store-ids)

**The flake.** `tests/test_dp_store.py::test_new_ids_are_unique` failed about 1 run in 50. `DemoStore.new_id` was
`<prefix>_<yyyymmddHHMMSS UTC>_<4 hex>`, so 50 ids drawn within one second collided ~1.9% of the time (birthday
odds over 65,536). The test with 2000 ids failed every run on the old code.

**Now** (`src/demo_pipeline/store.py`):
- The prefix and timestamp are unchanged: `human_YYYYMMDDHHMMSS_`. Experiment tags such as `human_2026*` glob on
  it.
- The suffix is 8 hex digits (`ID_SUFFIX_BYTES = 4`).
- An id is never issued twice in one process (`_ISSUED`). That makes uniqueness certain within a process, not just
  likely.
- `store.new_id(...)`, called on a store, also never returns the name of a folder that already exists, live or under
  `demos/_discarded`. It draws again, up to 20 times, then raises "no free id"; that can't happen by chance.
- `DemoStore.new_id(...)`, called on the class, does no folder check. Job ids and the TeleopSession default use it
  that way, and it still works.
- The live sink (`sim_worker/scripts/teleop_sink.py`) now passes `new_id=lambda: store.new_id("human")`, so a take
  can never land on an existing folder.

**Old 4-hex ids stay valid.** I searched py, ts, tsx, mjs and ps1 for anything assuming 4 hex. The only hit was the
old test's own regex. Nothing else parses the suffix:
- Store ids only need `[A-Za-z0-9_-]+`.
- The relay passes `demo_id` as a string.
- The web only displays it.
- `sim_eval/overnight.py` splits seed-file names, not demo ids.

`test_old_four_hex_ids_stay_valid_next_to_new_ones` saves, reads, lists, globs (`select_ids(tag="human_2026*")`) and
discards a real 4-hex id next to a new 8-hex one.

**Tests:** `tests/test_dp_store.py`. The format on a store and on the class; 2000 unique ids both ways; skipping an
existing folder and a `_discarded` one; no repeats without folders; the loud give-up; old ids next to new.

**Full suite, 3 runs in a row** (`uv run --no-sync pytest -q` from the repo root): 2035 passed, 15 skipped, 0 failed each
time (6:38, 6:36, 7:20). That is pm/live-11 2abc94e plus the 4 new store tests.
