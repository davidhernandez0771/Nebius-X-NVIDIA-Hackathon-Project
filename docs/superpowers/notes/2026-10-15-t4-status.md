## Decisions

- **Fixture.** The TS test asserts that its output equals the committed
  `__fixtures__/hand_pose_msg.json`; the test never writes it.
  - The fixture values were computed independently with a node one-liner from the same fixed
    landmarks, not by running `toHandPoseMsg`.
  - Change the fixture deliberately, together with both sides.
- **`wrist_uv` at the image edge.** MediaPipe landmarks can fall slightly outside [0, 1].
  - The TS builder clamps `wrist_uv` to [0, 1]. The Python model rejects out-of-range values
    as the plan says, so edge hands are clamped, not dropped by the relay.
- **Degenerate hands.** A zero-width palm or a NaN landmark becomes `tracking_ok: false`
  (last values kept) in TS. Otherwise the backend would reject it, since palm must be > 0
  while tracking.
- **`HandPoseMsg` strictness.**
  - `extra="forbid"`; NaN and inf are rejected.
  - `yaw_rad` must lie in [−π, π]; `frame_w` and `frame_h` must be > 0; `t_ms` ≥ 0.
  - `palm_width` and `pinch_ratio` must be ≥ 0, and palm > 0 only when `tracking_ok`.
  - `wrist_uv` must lie in [0, 1] always: stale values were valid, and 0 is valid.
- **`Calibration`** validates that every (min, max) pair is ordered.
- **`GripperLatch`** thresholds are constructor arguments (defaults 0.35 / 0.45). It holds on
  `tracking_ok: false` whatever the stale pinch says.
- **Relay.**
  - It accepts, then closes, with **4409** for a duplicate role and **4400** for an unknown role
    (the 4400 code is my choice).
  - The validation error `detail` is pydantic's `str(ValidationError)`.
  - A send failure to a vanishing sim is swallowed, and its handler reports the disconnect.
  - The sim socket's incoming messages are read and ignored, for now.
  - `GET /teleop/status` is exactly as in the plan, without the app's usual `/api` prefix.
    There is no Vite proxy, so the frontend must call the backend origin directly
    (CORS allows `localhost:5173` for HTTP).
- **Throttle (TS).**
  - `MIN_INTERVAL_MS = 33`: a frame is sent if at least 33 ms passed since the last send.
    I chose 33, not 33.3, so a 30 fps camera with jitter is not halved to 15 Hz; the worst
    case is about 30.3 messages per second.
  - Untracked messages also need at least 200 ms since the last untracked send. The first
    loss goes out at once, so the sim's latch holds promptly.
  - Messages are dropped, not queued, while the socket is not open.
- **`TeleopClient`.**
  - `constructor(url, WebSocketImpl = WebSocket)`; the second argument is injectable for tests.
  - `onStatus(cb)` returns an unsubscribe and reports `{socketOpen, simConnected, lastError}`.
- **`PINKY_MCP = 17`** is a local constant in `handPoseMessage.ts`, because
  `hand/contracts.ts`'s `LANDMARK` table has no entry for it and I may not edit that file.

## For the sim worker (T2)

- **Connecting.** Connect to `ws://<backend>/ws/teleop?role=sim`. Each incoming text frame is
  one `HandPoseMsg` JSON, already validated by the backend. Parse it with
  `HandPoseMsg.model_validate_json(text)`.
- **Per message:**
  - Call `gripper = latch.update(msg)` on every message, tracked or not.
  - If `msg.tracking_ok`, set `target = to_ee_target(msg, calib)`.
  - Otherwise keep the previous target. `to_ee_target` on an untracked message returns a
    finite pose built from stale or zero fields (x clamps to 0.30), not a meaningful one.
  - Spec 8.1: pause recording if tracking is lost for more than 0.3 s; use `msg.t_ms` gaps.
- **Rates.** Messages arrive at about 30 Hz; recording is at 50 Hz in sim time, so hold or
  interpolate the latest target between messages.
- **Reconnects.** Only one sim may connect; a second gets close code 4409. Reconnect after a
  drop. The browser is told `sim_connected` automatically.
- **Live tuning (first session).**
  - `invert_y`, `invert_z`, and the yaw sign may need flipping, depending on where the
    camera and the user stand relative to the robot.
  - `yaw_rad` is raw-image yaw. The plan applies no mirroring to it, unlike `u`. If turning the
    hand turns the gripper the wrong way, flip it via `yaw0` / a sign in the calibration: that
    needs a small `Calibration` addition, which I did not make because it isn't in the plan.
  - `palm_far` / `palm_near` set the x (depth) range; measure them per user and camera.
- **Orientation.** The quaternion is `(0, cos(θ/2), sin(θ/2), 0)` (wxyz): gripper down,
  rotated by θ = clamp(yaw − yaw0, ±π/2) about world z.

## 2026-10-16 — Task 4: `store.py` done (`df3c2c9`)

- `src/demo_pipeline/store.py`, `DemoStore(root=data_dir())`; `tests/test_dp_store.py`: 36 tests.
- **Full suite (fresh run):** 54 failed, 320 passed, 1 skipped. The failing set is identical to
  the baseline's.
- **Layout:** `<root>/demos/<id>/{demo.json, diagnosis.json, passport.json, episode/}`.
  `diagnosis.json` is `{"source", "model_id", "diagnosis"}` (`StoredDiagnosis`, validated).
- **Decisions:**
  - **Safe ids.** An id is a folder name, so it must match `[A-Za-z0-9_-]+`. Any other id is
    "not found" (`KeyError`) on every read and on `episode_dir`, and a `ValueError` on
    `save_demo`. This stops a URL id like `../x` from escaping the store.
  - **`new_id` uses UTC** for the timestamp and `secrets.token_hex(2)` for the 4 hex.
  - **`lineage(id)` includes `id` itself, last**, so it can go straight into `Passport.lineage`
    ("human demo id first, this demo last"). A missing ancestor raises `KeyError`; a
    `parent_id` cycle raises `ValueError`.
  - **Diagnoses and passports need the demo.** Saving or getting them for an unknown demo
    raises `KeyError`; a known demo without one returns `None`. The diagnosis source must be
    `nemotron`, `rules` or `none` (`ValueError` otherwise).
  - **`save_demo` overwrites** an existing id. `has_demo(id)` was added so the route can refuse
    a duplicate POST.
  - **Corrupt files.** `get_demo` raises pydantic's `ValidationError` (a `ValueError`) for a
    corrupt `demo.json`. `list_demos` skips unreadable or corrupt demos with a log warning,
    so one bad folder does not break the list.
  - **Newest first** means `created_at` descending, then id descending as a tie-break.
  - **Atomic writes:** `tempfile.mkstemp` in the same folder, then `os.replace`. On failure
    the temp file is removed and the old file is left intact (tested).
- **Purity:** stdlib + pydantic only.

    gated by the metrics.
