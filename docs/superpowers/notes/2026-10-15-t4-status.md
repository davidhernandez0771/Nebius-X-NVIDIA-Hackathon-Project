## Decisions

- **Image cap.** Added `MAX_IMAGES = 8` and `select_frames()` in `diagnose.py`. They evenly
  subsample the front frames, keeping the first and last, to 7 + wrist (or 8 with no wrist
  frame). The prompt captions match the frames actually sent.
  - **Lead:** update spec 8.3 (Changes section). You might choose 7 frames upstream.
- **`chat_vision` delegates to `chat_vision_images`.** It keeps its own defaults (`image/jpeg`,
  `max_tokens=1024`), so there is no duplicated request/logging code. The old tests still pass.
- **Prompt generated from the schema.**
  - The repair menu lists each op's fields from the pydantic op models.
  - Issue types and segment names come from the schema `Literal`s.
  - Short help text per op and issue lives in dicts in `diagnose.py`. A new schema op without
    help text raises `KeyError`, so drift fails loudly.
- **Example JSON in the prompt.** It uses a `jitter`/`smooth` example, not a pause, so it does
  not prime the model toward the pause the smoke test checks for.
- **Errors in `diagnose`.**
  - Only `DiagnosisError` triggers the retry.
  - `nebius_llm` errors (auth, 429, 400, …) propagate unchanged; the caller decides on the
    rules fallback.
  - The retry prompt is the original prompt plus the rejection message.
- **`parse_diagnosis`.** Takes the first `{` to the last `}`, per the plan. A reply with a stray
  `{` in prose before the JSON would fail and get retried.
- **Smoke script.**
  - It adds the one-token calibration call only when the diagnose call needed no retry, so a
    run makes at most 2 calls.
  - It refuses to run once the log holds 3 nemotron-vl calls.
  - Frames go to `data/smoke_diagnose/` (git-ignored).
