## Decisions (choices the plan left open)

### Environment

- `uv sync --all-extras` printed a warning: an inherited `VIRTUAL_ENV` points at the OneDrive
  `.venv`. uv ignores it and uses `C:\venvs\pm-t1`, so this is harmless.
- Bare `python` in the Git Bash shell fails ("uv trampoline failed to spawn"), so always use
  `uv run python`.
- The code was not run in the Isaac env (Python 3.12, numpy 2.3.1, pydantic 2.14.1). It uses no
  3.13+ syntax and only long-standing numpy APIs.

### measure

- **Windows:** each window is `[t0, t1)` and the last one includes the end. Windows start at
  `t[0]`.
- **Gripper:** a window's gripper value is the majority; a tie counts as closed (1).
- **Empty range:** `jerk_rms` over a range with no steps returns 0.0.
- **`gripper_events`:** if the gripper starts closed, the first close is `t[0]`. If it never
  reopens, it returns `(t_close, None)`.

### rules

- **Still runs:** a run of still steps a..b means "still from `t[a-1]` to `t[b]`". `speed[i]` is
  the motion into step i, so the reported pause starts when the hand stopped.
  - A still run that touches the start or the end counts as `idle_start_end`, never as `pause`.
- **Jitter floor (my own addition):** a window is jitter only if its jerk_rms is above
  **max(3 × median, 20 m/s³)**.
  - Without the floor, a demo with long holds has a median near 0, so smooth motion would be
    flagged.
  - Measured on a synthetic min-jerk demo: windows ≤ 4.2 m/s³ (median 1.8). 1 mm noise gives
    ~120 m/s³.
  - This is `JITTER_MIN_JERK`; tune it on real webcam demos.
- **Jitter spans:** consecutive jittery windows merge into one jitter issue and one
  `smooth(strength="med")` op.
- **Abrupt stops:** an instant stop from ~0.2 m/s (the synthetic "inserted hold") is a real jerk
  spike, so it also gets a jitter finding next to the pause.
  - My first tests asserted "pause only" and "0.2 s hold → keep", which is more than the plan
    asks. I relaxed them to the plan's requirements: one `pause` plus a matching
    `remove_pause`, and no pause for 0.2 s.
  - The investigation is recorded in the commit's tests.
- **Idle trim:** it never starts after the first close, and it keeps 0.5 s after the last open
  (`RELEASE_MARGIN_S`) so the release can finish.
- **Discard output:** `segments=[]`, one `other` issue ("the gripper never closes"),
  `repairs=[discard]`.
  - This way, sending the diagnosis to `apply_repairs` raises `DiscardDemo` with no special
    case.
- **Partial demos:** if the gripper closes but never reopens, the segments are approach + carry
  (to the end).

### repair

- **Grid snapping:**
  - `retime` and `replan_transit` snap t0/t1 to the nearest 50 Hz step.
  - Their new span length is a whole number of steps (`retime` rounds, `replan_transit` rounds
    up), so every sample after the span is an exact copy. That is how "endpoint poses unchanged
    within 1e-6" holds.
- **`replan_transit` timing:** it changes the duration (the new path is longer at the same
  average speed), so it also updates the time map.
  - If the original span barely moved, it uses a speed floor of 0.05 m/s
    (`MIN_TRANSIT_SPEED`).
- **`trim`** widens its range so it keeps the open step just before the first close and the last
  open (spec 8.4 invariant). There is a test for this.
- **`remove_pause`** does not raise if the gripper changes inside the span. A single change moves
  to the stitch, so it is preserved.
- **`recenter_grasp`** anchors on the real 0→1 close nearest the given `t`. That makes the ±2 mm
  guarantee hold when Nemotron's `t` is a few steps off.
- **`smooth`** fades to 0 within 0.1 s of every gripper event (as the plan says) **and** of the
  span's two edges. This prevents a step at the span boundary.
- **`apply_repairs`:**
  - Mapped times are clipped to the current duration.
  - An op whose mapped span shrinks below half a step is skipped (for example, a smooth that lay
    entirely inside a removed pause).
  - It assumes the input trajectory starts at t = 0. The output always does.

### multiply

- **Lift and blend:** "end of lift" is `t_close + 1.0 s`. The 0.5 s min-jerk blend runs forward
  from there, so the grasp and lift are exactly cube-relative.
  - Positions blend linearly by the min-jerk weight; quaternions slerp.
- **No grasp:** `transform_trajectory` raises `ValueError` for a demo that never closes.
- **Edge gap:** the distance between axis-aligned footprints. The cube's footprint is its yawed
  bounding box (half-size 0.025·(|cos|+|sin|)); the bin's is 0.11.
- **Sampling:** bin yaw is always 0. Rejection sampling gives up with `RuntimeError` after 10,000
  tries.
- **Blend test threshold:** `test_blend_has_no_jump` uses a 3 cm/step limit, not 1 cm.
  - With that scene the two transforms differ by ~0.25 m at the lift end, so a 0.5 s min-jerk
    blend peaks near 1.9 cm/step. A missing blend would jump 25 cm.
- **Shared slerp:** `multiply.py` reuses `repair._slerp` instead of keeping a second copy.

### Decisions

- **Pauses are a time warp, not a pasted hold.** The hand slows to a stop over 0.2 s (cosine
  rate), holds, and starts again over 0.2 s. A pasted hold stops instantly from ~0.2 m/s, which
  is a jerk spike no person makes (sprint 1 saw it raise a jitter finding). The truth pause is
  the exact zero-rate hold. The rules' still detection extends ~1 step into each ramp.
- **Pause placement:** at a step where the clean hand moves ≥ 0.05 m/s, with the pause *and its
  ramps* ≥ 0.3 s from the start, the end and every gripper event, and ≥ 1.0 s (source time)
  from other pauses so two never merge. If there is no room, `ValueError`.
  - Without the "moving" condition, a pause could land in the scripted expert's 0.5 s gripper
    hold and merge into a still run that contains the gripper change, which the rules (correctly)
    do not call a pause. The truth would then be unfindable.
- **Grasp offset:** applied on the clean timeline before the warp. Full offset through the
  approach, the close and the lift (`multiply.LIFT_S` = 1 s after the close), then a 1 s min-jerk
  fade, so the release is on the original path. z is unchanged.
- **Jitter** is added last, on the degraded timeline, over the whole demo (holds included):
  webcam noise is in real time and everywhere. Gaussian kernel with -3 dB at 6 Hz
  (σ = 22 ms); zero mean; scaled so each axis' std is exactly `jitter_mm`. Its truth is one
  `jitter` issue over `[0, T]`.
- **Truth for whole-demo issues:** `slow` (only when `slow_factor > 1`) and `jitter` span
  `[0, T]`. `grasp_off_center` is a point issue, `t0 == t1 ==` the degraded close time.
- **RNG order** (part of "same seed → same output"): offset angle, pause times and lengths,
  jitter noise. Draws are skipped for disabled degradations.
- The output is always on a 50 Hz grid from t = 0. The grid may run up to one step past the
  warp's end; that tail is a hold and belongs to the idle-end truth when there is one.

### Decisions

- **Same still detection as the rules:** `rules._still_runs` with `rules.STILL_SPEED`, read at
  call time, so Task 5's tuning applies here too. Only runs ≥ `MIN_STILL_S` (0.4 s) count, so a
  short natural slow-down cannot rescue a spurious pause.
- **pause / remove_pause** snap to an *interior* still run with the gripper unchanged (the rules'
  pause definition). A hold while the gripper acts is dropped: removing it would cut the grasp.
- **idle_start_end** snaps to the rules' idle spans: `[start, min(still end, first close)]` and
  `[max(still start, last open + 0.5 s), end]`.
- **trim** is a *keep* range, so its edges snap: an edge the model moved inward goes to the idle
  edge (or back to the demo's end if there is no idle there). A trim that ends up keeping
  everything is dropped.
- **Several candidates:** the one with the largest overlap wins. A point issue (`t` only) must
  lie inside a still run, and comes out as a `t0`/`t1` range.
- **Duplicates** (two window-aligned pauses on one still run) collapse into one.
- **"Drop the issue and its repair":** issues and repairs are snapped independently. Issues and
  repairs are not linked in the schema, and in practice the model gives a pause and its
  `remove_pause` the same range.
- `decision` changes only from `repair` to `keep`, when no repairs are left. A discard passes
  through (its `discard` op is untouched).

  tests. Among them are `test_clean_scripted_demo_is_keep_with_three_segments`, the rules'
  0.9 s pause test and the refine tests. It does so by flagging the expert's normal
  slow-downs: about 360 false pauses per 200 clean demos, precision ≈ 0.4. Every value that keeps
  the tests green has pooled F1 = 0, so no improvement. The plan's rule ("only if F1 improves,
  and keep every existing test green") therefore rules out every change.
- A false pause is harmful, not just noisy: `remove_pause` on real motion cuts it out of the demo.
- **Held-out check** (seeds 1000–1199): 0.01 → pooled F1 0.00, F1 @0 0.98 (pause 198/14);
  0.15 → pooled F1 0.33, P 0.39. It matches the tuning set.

**Root cause of the jitter-0 pause FPs (11 on seeds 0–199):** all 11 are on *slowed* demos,
~0.4 s long, mid-carry, at the lift → carry waypoint. The scripted expert stops at every
waypoint (min-jerk to zero velocity), so the hand is below 0.01 m/s for ~0.25 s at each join, and
a 1.2–1.6× slow factor stretches that past `MIN_STILL_S`. The hand really does stop there, so this
is not a rules or degrade bug. The truth simply does not count the expert's own stops.

### Known limits (measured)

- **~4% of pauses are missed under tremor:** a pause within ~0.3–0.9 s of a gripper hold, or
  just before the end-of-demo stillness, blurs into it. The merged run then contains a gripper
  change, or touches the end, so it is not a pause.
- **Short, fast stops vanish:** an *instant* 0.6 s stop from ~0.27 m/s bottoms out at 0.032 m/s
  on the smoothed path. `degrade`'s pauses (0.2 s ramps, ≥ 0.5 s) are found ~96% of the time.
- **0.1 mm tremor** falls under the gate (clean range), so it takes the raw path: 10 pause FPs and
  48 idle misses per 200 demos there.
- The gate assumes ~50 Hz demos; `position_noise` scales with the time step for smooth motion.

### Decision: degrade reports the stops, and the scorer treats them as don't-care

- **Why not count them as truth?** They were not injected. The ablation measures finding human
  defects, and missing the scripted expert's stop-and-go is no miss.
- **Why not leave them out?** They are real stops (the hand is below 0.03 m/s, at zero velocity
  at the join), so flagging one is not a false alarm. Before this, all 11 jitter-0 "FPs" were
  exactly these.
- **So: don't-care,** the standard "ignore region" of detection benchmarks.
  - Real truths are matched first. A leftover prediction ≥ 50% inside a same-type don't-care
    span is `ignored` (its own column, never hidden). A don't-care span is never an FN.
  - `ignored` is neither TP nor FP, so it does not enter P/R/F1.
- **degrade is the place that knows them:** they are found on the path *before* the tremor is
  added, outside the injected holds, interior only, with the gripper unchanged, < 0.03 m/s for
  ≥ 0.1 s. 0.03 m/s is above every still threshold in use (0.01 raw, 0.02 smoothed).
  `test_under_tremor_every_rules_pause_is_injected_or_an_expert_stop` pins that it covers what the
  noisy detector flags.
- **Opt-in** (`expert_stops=False` by default). Every other caller still gets exactly what was
  injected. The scoring script turns it on.
