## Decisions

1. **Routes under `/pm/`.** SANT already owns `/review`, so the new pages don't shadow anything.
2. **Perfect job contract (T4 hasn't merged it).**
   - Calls: `POST /demos/{id}/perfect?diagnoser=rules|nemotron`, then poll `GET /jobs/{id}`
     every 1 s.
   - `normalizeJob()` (`web/src/pm/jobs.ts`) accepts `id` or `job_id`, and the statuses
     queued/pending, running, succeeded/success/done/completed and failed/error. An unknown
     status fails loudly instead of polling forever.
   - The repaired demo id comes from `result.repaired_demo_id`, `result.demo_id` or
     `result.repaired_id`.
   - **T4: if your shape differs, change `normalizeJob` and its tests.**
3. **Mock only when the route is missing.**
   - A missing route means FastAPI's bare 404 `"Not Found"`, or a 405. Only then does the page
     run an in-browser mock job, labelled "Mock job: nothing is perfected".
   - The mock never links a demo.
   - A 503, 409 or any other error is shown as-is, never hidden behind the mock.
4. **Polling limits.** One dropped poll is tolerated. Three errors in a row fail the job with
   the backend's message. 600 polls (about 10 min) fail it with "timed out, may still be
   running". Leaving the page stops polling.
5. **The diagnoser defaults to rules.** Nemotron is labelled "billed Token Factory call". No
   number is shown, so no cost figure needs a source.
6. **Record streams; it doesn't save demos.** Sim-side recording isn't connected to this page,
   and the page says so. "Calibration" is a framing check against
   `demo_pipeline.teleop.Calibration`'s defaults (u 0.2–0.8, v 0.15–0.85, palm 0.06–0.14),
   mirrored in `record/framing.ts`. **Update both together.**
   - The webcam image itself isn't shown, because `TrackingAdapter` doesn't expose its video.
     The page draws the landmarks on a canvas instead.
   - MediaPipe loads through a dynamic import, only on Start.
7. **Before/after clips → hand-speed plot.** The backend serves no replay frames yet. The page
   says so and compares the speed profiles of the demo and its parent.
8. **Partial passport.** There is no passport route, so the card shows what `GET /demos/{id}`
   and the diagnosis give. It says "Physics check: not served by this backend yet".
9. **Yield on Dataset.** True yield needs the failed attempts, which the store doesn't keep.
   The page says so and shows ratios of stored demos only.
10. **Sample numbers.** The values in `results.sample.json` are invented placeholders, and the
    file's `note` field says so. Only MimicGen's 38–74% is a published figure (spec §5).

## Design

The brief said to use the SANT visual language, so the tokens, glass cards, Instrument Serif
titles and rail are unchanged. Inside that, each color has one job on these pages:

- **warm:** what the model or the human claims (issues, raw input, sample data);
- **teal:** what code did or physics verified (repairs, perfected/variant demos);
- **danger:** failures;
- **muted:** structure.

The one bold element is the Review strip: three lanes that read top to bottom as "the AI
decides, code acts". I avoided all-caps eyebrows, monospace labels, middle-dot meta strings and
arrow suffixes. Demo ids and the Record clock use the sans face, because the display serif's
old-style 0 reads as "o".
