## Decisions

1. **Routes under `/pm/`.** SANT already owns `/review`, so the new pages don't shadow anything.
2. **Perfect job contract (T4 hasn't merged it).**
   - Calls: `POST /demos/{id}/perfect?diagnoser=rules|nemotron`, then poll `GET /jobs/{id}`
     every 1 s.
   - `normalizeJob()` (`web/src/pm/jobs.ts`) accepts `id` or `job_id`, and the statuses
     queued/pending, running, succeeded/success/done/completed and failed/error. An unknown
     status fails loudly instead of polling forever.
   - The repaired demo id comes from `result.repaired_demo_id`, `result.demo_id` or
     `result.repaired_id`.
   - **T4: if your shape differs, change `normalizeJob` and its tests.**
3. **Mock only when the route is missing.**
   - A missing route means FastAPI's bare 404 `"Not Found"`, or a 405. Only then does the page
     run an in-browser mock job, labelled "Mock job: nothing is perfected".
   - The mock never links a demo.
   - A 503, 409 or any other error is shown as-is, never hidden behind the mock.
4. **Polling limits.** One dropped poll is tolerated. Three errors in a row fail the job with
   the backend's message. 600 polls (about 10 min) fail it with "timed out, may still be
   running". Leaving the page stops polling.
5. **The diagnoser defaults to rules.** Nemotron is labelled "billed Token Factory call". No
   number is shown, so no cost figure needs a source.
6. **Record streams; it doesn't save demos.** Sim-side recording isn't connected to this page,
   and the page says so. "Calibration" is a framing check against
   `demo_pipeline.teleop.Calibration`'s defaults (u 0.2–0.8, v 0.15–0.85, palm 0.06–0.14),
   mirrored in `record/framing.ts`. **Update both together.**
   - The webcam image itself isn't shown, because `TrackingAdapter` doesn't expose its video.
     The page draws the landmarks on a canvas instead.
   - MediaPipe loads through a dynamic import, only on Start.
7. **Before/after clips → hand-speed plot.** The backend serves no replay frames yet. The page
   says so and compares the speed profiles of the demo and its parent.
8. **Partial passport.** There is no passport route, so the card shows what `GET /demos/{id}`
   and the diagnosis give. It says "Physics check: not served by this backend yet".
9. **Yield on Dataset.** True yield needs the failed attempts, which the store doesn't keep.
   The page says so and shows ratios of stored demos only.
10. **Sample numbers.** The values in `results.sample.json` are invented placeholders, and the
    file's `note` field says so. Only MimicGen's 38–74% is a published figure (spec §5).

## Design

The brief said to use the SANT visual language, so the tokens, glass cards, Instrument Serif
titles and rail are unchanged. Inside that, each color has one job on these pages:

- **warm:** what the model or the human claims (issues, raw input, sample data);
- **teal:** what code did or physics verified (repairs, perfected/variant demos);
- **danger:** failures;
- **muted:** structure.

The one bold element is the Review strip: three lanes that read top to bottom as "the AI
decides, code acts". I avoided all-caps eyebrows, monospace labels, middle-dot meta strings and
arrow suffixes. Demo ids and the Record clock use the sans face, because the display serif's
old-style 0 reads as "o".

## 2026-10-16 — Task 1: relay control and status messages

`src/app/routers/teleop.py`:

- **`ControlMsg`** (browser → sim): `{"type": "control", "action": "record_start" | "record_stop" | "reset_scene"}`.
  - Any browser message with a `type` key takes this path; all other messages go down the
    unchanged `HandPoseMsg` path.
  - An invalid control, or one sent while no sim is connected, gets an `error` back.
  - Controls are forwarded verbatim and are not counted in `messages_forwarded`. That counter
    still counts hand poses only, so `/teleop/status` keeps its exact shape.
- **`SimStatusMsg`** (sim → browser): `recording`, `steps` (≥ 0), `demo_id`, `last_result`,
  plus `paused` (default false), which I added for spec 8.1's "recording pauses; the user is
  told".
  - A valid one is forwarded to the browser and cached, so a browser that reconnects gets it
    right after its `status` message.
  - The cache is cleared when the sim disconnects.
  - An invalid one gets an `error` back to the sim.

## 2026-10-16 — Task 2: `TeleopSession`, the pure state machine

`sim_worker/teleop_session.py` (numpy + pydantic + `demo_pipeline` only; no torch, no Isaac):

- **States:** `idle` → `recording` → `saving` → `idle`.
  - `record_start` while recording is refused ("already recording").
  - `record_stop` while idle is a no-op.
  - `reset_scene` while recording is refused ("stop recording first").
  - An unknown action raises `ValueError`.
- **Each `step()`:** the latest `HandPoseMsg` → `to_ee_target` + `GripperLatch` → `driver.apply(target, gripper)` → `driver.read_state()`.
  - While recording and not paused, it appends the commanded target and the measured `StepState`.
  - The Trajectory is at `t = k × 0.02` (sim time), whatever the wall-clock pace.
- **Choices:**
  - **It follows the hand while idle too**, so the person can line up before Start.
  - Before any hand, and after `reset_scene`, it **holds the driver's current tool pose**,
    with the gripper open. `reset_scene` also forgets the last hand and latch, so the arm
    doesn't jump back to the old target.
  - **Lost tracking (spec 8.1):** a dropout of ≤ 0.3 s (wall clock since the last tracked
    message) is recorded as a hold of the last target, with the latch holding the gripper.
    Past 0.3 s the status says `paused` and steps are not recorded, so the pause is cut out
    of the demo. No messages at all counts as lost.
  - **`human_seconds`** = wall clock from start to stop, pauses included: it is the human's
    time.
  - **< 2 steps** → "not saved". A `save_fn` exception → "save failed: …", and the session
    returns to idle.
- **`make_store_saver(store, bin_inner=...)`:**
  - writes `store.save_demo`, then the episode at `store.episode_dir(id)` (steps.npz,
    signals.npz, camera PNGs) where `/demos/{id}/diagnose` and `/perfect` look for it;
  - runs `check_success` on the live signals, with the reached-vs-commanded residual as the
    reach signal (as replay does with feedforward);
  - returns "saved <id>: verified success" or "saved <id>: not verified (reasons)".
- **Tests:** `tests/test_sim_teleop_session.py`, 26, with a fake driver and a fake clock.
  - Red first: collection failed on the missing module.
  - One assertion was mine and wrong: the pause boundary is 15 ticks = 0.30 s in floating
    point, not 16. I fixed the test's bounds, not the code.
  - **Mutation checks, all caught:** pause at 2 × the limit (3 tests fail), not holding the
    target while lost (1), `human_seconds` from sim time (1).
- **Runs:** SANT 25 passed + 1 skipped (PIL). **Isaac's python: 26 passed**; there,
  `demo_pipeline` is pm-t2's editable install.
- **Full suite:** 875 passed, 0 failed, 13 skipped (fresh run before this commit).
